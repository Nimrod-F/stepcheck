\section{Approach}
\label{sec:approach}

\subsection{A two-layer analysis model}

\tool{} separates what can be checked from \asl{} alone from what needs recovered
semantics. \emph{Native} analyses (Layer~A) are sound and require no annotations:
structural well-formedness, and \asl{}-semantic data-binding checks such as a
\texttt{waitForTaskToken} task that never passes its task token, misuse of the
\texttt{\$\$.Map} context, and syntactically invalid JSONPath payloads.
\emph{Semantic} analyses (Layer~B) ---typestate, retry safety, compensation, and
typed contract compatibility--- consume an \emph{annotation} layer that records the
task semantics \asl{} omits. The annotation layer has two sources, in priority
order: explicit annotations (authored by hand or produced by the typed DSL
frontend), and \emph{inference} that supplies defaults from naming and resource
conventions. Findings derived from inferred facts are reported at \emph{warning}
severity, while findings derived from declared facts are \emph{errors}; this single
rule keeps confidence visible throughout the tool's output.

\subsection{Workflow model}
\label{sec:approach:model}

We model a workflow as a graph of states with a designated start. A \emph{task} is
characterised, beyond its control-flow successors, by four pieces of semantic
information used by the checks:

\begin{description}
  \item[Contract.] A task consumes an input record and produces an output record. We
        write a task as $T : A \rightarrow B$, where $A$ and $B$ name record types
        (sets of fields). Two adjacent tasks $T_1 : A \rightarrow B$ and
        $T_2 : C \rightarrow D$ \emph{compose} only if $B$ provides every field $C$
        requires. Natively (without declared types) the contract layer instead checks
        that JSONPath references resolve to data the workflow actually binds.
  \item[Typestate.] Each task also advances a \emph{business state}: $T$ moves the
        workflow from state $s_{\mathrm{in}}$ to $s_{\mathrm{out}}$. A workflow is
        well-ordered when each task consumes the state its predecessor produced. An
        optional \emph{protocol} lists the permitted state transitions
        (e.g.\ \emph{created\,$\to$\,reserved\,$\to$\,paid\,$\to$\,shipped}), so that
        a task performing an undeclared transition is rejected.
  \item[Idempotency.] A task is \emph{idempotent} if repeating it causes no additional
        external effect. Idempotent tasks may be retried freely; non-idempotent tasks
        may not be retried on broad error classes.
  \item[Persistence and compensation.] A task is \emph{persistent} if it commits a
        durable resource (a reservation, a charge, a created record) that a later
        failure should undo. A persistent task needs a \emph{compensation}: an
        explicit handler or a \texttt{Catch} path to a compensating state.
\end{description}

This vocabulary is deliberately lightweight---there is no separate formal calculus to
maintain---yet it is exactly what the four checks of Section~\ref{sec:analyses}
consume. We illustrate it with the order workflow throughout.

\subsection{The annotation layer}
\label{sec:approach:annot}

Explicit semantics are supplied either through a \emph{sidecar} file attached to an
existing \asl{} workflow (Listing~\ref{lst:sidecar}) or, for greenfield workflows,
through a typed builder DSL that emits both the \asl{} and its annotations
(Listing~\ref{lst:dsl}). The two routes resolve to the same internal representation,
so the analyses are agnostic to how a workflow was authored.

\begin{lstlisting}[style=base,caption={A sidecar annotation (TOML), excerpt.},label={lst:sidecar}]
[schemas.OrderReserved]
fields = ["orderId", "amount", "reservationId"]
[tasks.ChargeCard]
idempotent = false
persistent = true
compensation = "RefundPayment"
state_in = "OrderReserved"
state_out = "OrderPaid"
\end{lstlisting}

\begin{lstlisting}[style=dsl,caption={The order workflow in the typed DSL (excerpt).},label={lst:dsl}]
Builder::new("order-processing", "CreateOrder")
  .schema("OrderReserved", &["orderId","amount","reservationId"])
  .protocol("OrderReserved", "OrderPaid")
  .task("ChargeCard", "OrderReserved", "OrderPaid",
        /*idempotent*/ false, /*persistent*/ true,
        /*compensation*/ Some("RefundPayment"),
        /*next*/ Some("ShipOrder"), /*catch*/ Some("RefundPayment"))
\end{lstlisting}

\subsection{Inference of default annotations}
\label{sec:approach:infer}

Most existing workflows carry no annotations, yet their task names and resource ARNs
are highly conventional. \tool{} exploits this with a documented, configurable
heuristic that classifies each task from a lowercased \emph{signal} (its name, its
\texttt{Resource}, and parameters such as \texttt{FunctionName}). The heuristic uses
four small keyword sets: \emph{read} verbs (\texttt{get}, \texttt{list},
\texttt{describe}, \texttt{query}, \texttt{validate}, \dots) imply idempotent and
non-persistent; \emph{write} verbs (\texttt{create}, \texttt{charge}, \texttt{send},
\dots) imply non-idempotent; \emph{resource-acquiring} verbs (\texttt{reserve},
\texttt{pay}, \texttt{provision}, \texttt{putItem}, \dots) additionally imply
persistent; and \emph{notification} verbs/resources (\texttt{notify},
\texttt{publish}, \texttt{:sns:}, \dots) are non-idempotent but, being
fire-and-forget, never persistent. When no keyword matches, the heuristic
\emph{abstains}, leaving the task unclassified rather than guessing. Inference thus
yields a zero-effort default whose mistakes (Section~\ref{sec:eval}) are visible
(warnings) and correctable (an explicit annotation always wins).

\subsection{Architecture}

Figure~\ref{fig:arch} shows the pipeline. A \emph{frontend} lowers a surface syntax
to a format-agnostic intermediate representation (IR); annotation resolution
attaches declared and inferred semantics to the IR; a \emph{pass} pipeline runs the
five analyses, each emitting coded diagnostics; and an \emph{emitter} lowers verified
workflows back to \asl{}. The design is modular along two axes: a new input format is
a new \texttt{Frontend}, and a new check is a new \texttt{Pass}
(Section~\ref{sec:impl}).
