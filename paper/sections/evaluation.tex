\section{Evaluation}
\label{sec:eval}

We organize the evaluation around four questions plus one case study. RQ1 asks whether \tool{} detects
the defect classes that schema validators and workflow-soundness verifiers miss. RQ2 isolates the
central data-flow claim: when \code{SC1101} reports a missing field, is the report sound, and how much
of real \asl{} falls in the modeled fragment? RQ3 tests whether the findings generalize beyond the
core AWS sample corpus to unmodified workflows, real fixes, other formats, independent repositories,
and deployment artifacts. RQ4 measures whether \tool{} is cheap enough to run as a build-time gate.
The automotive case study then tests the checks and annotation workflow on a private production
rewrite.
The evaluation corpus is public and deployment-shaped. Its core is \textbf{193} AWS sample
workflows~\cite{awsServerlessPatterns}, mined exhaustively from every parseable \asl{} definition and
spanning the main \asl{} constructs, JSONata-mode, Distributed \texttt{Map}, and nine AWS services
plus six industrial-topology
\texttt{aws-samples} patterns including AWS Serverless Airline Booking
\texttt{ProcessBooking}, a canonical serverless benchmark~\cite{awsServerlessAirline}.
For external validity (\S~\ref{sec:eval:cncf}) we add \texttt{serverless-patterns} and AWS Solutions
Library deployment artifacts~\cite{awsServerlessPatterns,awsSolutionsLibrary}, CNCF Serverless Workflow
examples, and independent \asl{} from public repositories; these public artifacts are reproducible
stand-ins for proprietary definitions, which we complement with a private, anonymized automotive
case study (\S~\ref{sec:eval:automotive}). All experiments use a Rust~1.96 release build on a
Windows 11 laptop with an Intel Core i7-8550U CPU (4 cores/8 logical processors) and 16~GB RAM.

\subsection{RQ1: Detection power and baselines}
\label{sec:eval:mut}
\label{sec:eval:baseline}

\tool{} detects the semantic defect classes existing tools miss. On the 193 AWS sample
workflows~\cite{awsServerlessPatterns} we
inject one defect per applicable workflow crediting a detection only
when re-verification emits a fresh diagnostic naming the injected fault.
Across 616 mutants in six defect classes \textsc{StepCheck} detects
every one, with exact 95\% confidence intervals per class (Table~\ref{tab:baseline}).
The schema
validators---\texttt{statelint}~\cite{awsStatelint}, \texttt{asl-validator}~\cite{aslValidator}, and
AWS's \texttt{ValidateStateMachineDefinition}~\cite{awsValidateDefinition}---catch
the schema-level dangling transitions and broken bindings but none of the four semantic classes.
Because the mutation operators are ours, we also run a matched hard-mutant suite---\textbf{688}
mutants that keep each semantic fault but shift it just past the analysis's proof ($\top$) boundary.
Aggregate recall is \textbf{0.24} (162 of 688): the data-flow, contract, concurrency, and temporal
checks fall to $0$ once the fault crosses their $\top$ boundary, retry and compensation degrade to
$0.68$/$0.79$, and the schema-level structural check holds at $1.00$ (per-class breakdown in~\cite{stepcheck-repo}). Every miss is a premise the analysis
soundly lifts to $\top$, not a false alarm: a sound analysis (Theorem~\ref{thm:soundness}) declines
to report what it cannot prove, so these expected drops mark completeness boundaries---not
unsoundness---and show the checks are not tuned to our operators.
We also run three formal workflow-soundness verifiers
locally---Woflan~\cite{woflan}, BPMN Analyzer 2.0~\cite{bpmnanalyzer},
and BProVe~\cite{bprove}---encoding each \textsc{Asl} workflow into a
BPMN workflow net and crediting a verifier only on a fresh soundness
violation (Table~\ref{tab:woflan}).
They express only
the single control-flow class, dangling transitions (\code{SC0002}), catching it at Woflan $95\%$, BPMN
Analyzer $87\%$, and BProVe $69\%$. The four native classes that do not encode as workflow-net
soundness---data binding, retry safety, field flow, and temporal bounds---are silent for all three
formal verifiers, while compensation and concurrency are caught only when the injected fault also
manifests as a workflow-net soundness violation: at most $37\%$ for compensation and $5\%$ for
concurrency, far below \tool{}'s $1.00$ on both.
They also misclassify valid workflows---Woflan and BPMN Analyzer each
flag 16 of 193 (8.3\%) and BProVe 56 of 193 (29\%)---because
\textsc{Asl}'s multi-terminal termination is not a sound workflow net
under the single-sink definition these tools implement. Our encoding
deliberately preserves the distinct \texttt{Succeed}/\texttt{Fail}
terminals rather than merging them into a synthetic sink, since merging them would mask the failure-path structure the compensation analysis targets; 
the rejections reflect a definitional gap (\S\ref{sec:related}); StepCheck's Asl-native model accepts all 193.

\subsection{RQ2: Data-flow soundness and coverage}
\label{sec:eval:dataflow}

The flagship sound check \code{SC1101} (data flow) is measured separately from the six classes above:
as a no-false-positive check it fires zero times on the clean corpus, so we inject a missing-field read
into each of the \textbf{126 of 193} workflows that contain a document-field read the mutator can turn
into a missing read. 
With output-shape modeling \textsc{StepCheck} detects 88 (70\%); the
remaining 38 injected reads sit behind constructs the analysis soundly
lifts to $\top$---opaque task results or unmodeled
selectors---so silence there is the completeness boundary, not a missed proof. A proof-certificate checker certifies
all 88 reports by checking 1,146 finite widened-fixpoint postcondition
obligations, and a concrete execution oracle finds zero present-field
counterexamples (cf.~\cite{translationvalidation}). The check is practically relevant: 92\% of the corpus's
document-field references fall in the fragment it models exactly,
the rest lifting soundly to $\top$.



\subsection{RQ3: Real-world evidence and external validity}
\label{sec:eval:wild}
\label{sec:eval:cncf}

On the same 193 unmodified AWS sample workflows~\cite{awsServerlessPatterns}, an
inference-mode run emits 226 diagnostics: 181 advisory inferred-tier
warnings (SC3001/SC4001/SC4010) and 45 native-tier findings across
four codes, dominated by 33 unbounded callbacks (SC6001; per-code
breakdown in~\cite{stepcheck-repo}). We adjudicate all 45: a
code-disjoint verifier re-checks each finding's structural predicate
against its \textsc{Asl} source and confirms every one.
We do not treat the \textbf{181} inferred-tier warnings as
adjudicated defects here; the technical report~\cite{stepcheck-repo} separately calibrates the
name/resource inference that feeds them against gold task labels.
\tool{} also re-discovers real defects in deployed artifacts. In \textbf{39} mined fix-commit pairs,
a diagnostic appears only on the buggy revision in \textbf{7}; adjudication confirms \textbf{6}
genuine in-scope defects across data-flow, dead-branch (including an \code{SC1110}
unreachable subscriber branch), unbounded-callback, and structural classes
and rejects the 7th as an artifact---its finding vanished only because the fix deleted the flagged
task, not because the defect was resolved---while the other \textbf{32} pairs are out-of-scope
value, feature, or refactoring edits. In \textbf{three} user-filed issues---each quoting the verbatim
runtime error \tool{}'s sound tier prevents---\tool{} flags all three genuine \code{SC1101} defects;
on \textbf{two} further standalone definitions mined from independent repositories it flags one
non-idempotent SQS send retried on \texttt{States.TaskFailed} (\code{SC3001}) and correctly passes one
sound saga. Repository, commit, and issue
provenance are in the technical report~\cite{stepcheck-repo}; these results are existence evidence,
not a prevalence estimate.
Across a different workflow format, the front end lowers \textbf{66} CNCF Serverless Workflow examples
to the same IR. The structural, typestate, retry, compensation, concurrency, and temporal checks then
apply unchanged, and the mutation study catches every injected control-flow defect. Field-flow
generalizes less: only \textbf{12 of 66} examples declare records the sound \code{SC1101}/\code{SC1110}
checks can model. The other \textbf{54} are schema-free, so those checks stay silent rather than claim
coverage. Where CNCF declares JSON Schemas, \code{SC1010} enforces them exactly.
To test for overfitting, we ran \tool{} on \textbf{95} further ASL definitions from \textbf{16} public
repositories. It produced representative findings---a flow-sensitive missing field, a shared
DynamoDB write across \texttt{Parallel} branches, and a declared-tier uncompensated payment effect---on
workflows we neither authored nor curated \cite{stepcheck-repo}.
Finally, the CloudFormation front end reads the artifacts teams actually ship. Running \tool{} on the
\textbf{aws-samples/serverless-patterns} SAM templates~\cite{awsServerlessPatterns}, with no manual
extraction, covers \textbf{55} workflows and flags \textbf{13}. Two are sound-tier: a missing
\texttt{Default} (\code{SC0007}) and an unbounded callback (\code{SC6001}). On the enterprise \textbf{AWS
Solutions Library}~\cite{awsSolutionsLibrary} (\textbf{26} machines, partly CDK-generated) it flags
\textbf{14}, alongside several clean true negatives. Re-running the gate on six CDK-synth templates
catches every applicable mutation, including the semantic ones \texttt{asl-validator} silently accepts.
This moves the corpus from curated \asl{} to the deployment forms verification must meet.

\subsection{RQ4: Build-time cost and deployability}
\label{sec:eval:cost}
\label{sec:eval:roundtrip}
\label{sec:eval:industrial}

We evaluate both the build-time gate and verification cost on six industrial-topology workflows
totaling 65 recursive states, including four \texttt{aws-samples} Sagas~\cite{awsServerlessPatterns},
a Map-based ETL aggregator, and SAB \texttt{ProcessBooking}. As a gate, \tool{} runs at CI cost: we inject $0/1/5$
defects and, per level, compare the build-fail catch-rate against the local schema validator. On the clean set the validator accepts 5 of 6 workflows; its lone
rejection is the JSONata-mode ETL workflow, a validator-version lag on ASL's newer
\texttt{Assign}/\texttt{Arguments}/\texttt{Output} fields rather than a workflow defect. At a single
injected \emph{semantic} defect the gate fails the build on every workflow with an applicable mutation site, while the
validator flags \emph{none}: its only rejection is that same JSONata ETL it already misreads, not the
injected defect, which would therefore deploy. At five defects the gate again catches every workflow with applicable mutation sites, while the
validator flags only co-injected \emph{syntactic} faults, never a semantic one. Gate latency stays
below \textbf{21}\,ms at p95 (including process start): on six CDK-synthesized AWS Solutions
deployment templates, the same end-to-end gate costs p50/p95 \textbf{15.7/20.9}\,ms.
Verification is cheap: a workflow checks in a median $\approx$\textbf{25}\,$\mu$s (max
$\approx$1.1\,ms), adding no runtime component since it runs before deployment. 
The widened fixpoint converges on every committed input
($k =12$ depth; 262 definitions: 193 AWS samples, 66 CNCF
examples, and 3 issue-mined workflows; maximum 7 rounds). Scale is not a
concern either: a synthetic
\textbf{10{,}000}-state workflow verifies in $\approx$\textbf{31}\,ms, well under a one-second CI budget.
Finally, the emitter round-trips the 193-workflow corpus with exact
\textsc{Asl}-object equality for 192 of 193, and \textsc{StepCheck}-verified
definitions deploy unmodified and complete 100/100 live runs across
Express, Standard, and callback execution models~\cite{stepcheck-repo}.


\subsection{Automotive case study}
\label{sec:eval:automotive}
We also inspected an anonymized automotive packaging-service module: part of
an ongoing rewrite of a legacy production system into serverless services,
built entirely in CDK by a cross-country team of 12 engineers with uneven
Step Functions experience. Three Express workflows---\texttt{Borrowed},
\texttt{Universal}, and \texttt{ValidateSupplier}, with 15, 14, and 5
recursive \asl{} states---encode packaging business flows: request
validation, permission and supplier checks, persistence, and event
publication. An initial inference-mode run of \tool{}---before any
annotations, so contract-dependent findings are advisory and outside
Theorem~\ref{thm:soundness}---reported \textbf{40 findings}:
\textbf{25} retry/timeout mismatches (\code{SC6002}; Lambda tasks retrying
up to 126\,s against declared 10--20\,s machine timeouts), \textbf{10}
data-flow warnings (\code{SC1101}), and \textbf{5} concurrency warnings
(\code{SC5001}). The team then authored a declared-tier sidecar for durable
effects and data contracts; re-checking promoted the 5 concurrency and 7 of
the 10 data-flow warnings to \emph{errors}, confirming parallel writes to
the same durable resource and fields missing on some paths. The remaining
3 stayed inferred-tier warnings---\emph{not guaranteed by the contract
premise}, per Section~\ref{sec:approach:dataflow}---until the corrected
schema declared those fields optional; since the reads are guarded by
presence checks, the declared-tier re-run confirmed them consistent and the
warnings cleared, the expected outcome for handled-optional fields rather
than a silenced defect. Both severity tiers thus behaved as designed: no
error-level \code{SC1101} was refuted by the team, upholding
Theorem~\ref{thm:soundness}'s guarantee. A lead developer confirmed the
\textbf{12 errors} (\code{SC5001}, \code{SC1101}) and \textbf{25 timeout
warnings} as genuine, deployable defects; each was subsequently fixed. The
most critical: in \texttt{Universal}, a \texttt{Map} state's
\texttt{ItemsPath} read \texttt{\$.detail.items}, absent on
error-handling paths where \texttt{detail} is an error object; the failed
path read would pass \texttt{null} to the \texttt{Map} iterator, causing a
\texttt{States.Runtime} error---squarely in \code{SC1101}'s scope.
