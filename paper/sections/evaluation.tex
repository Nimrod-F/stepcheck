\section{Evaluation}
\label{sec:eval}

We evaluate \tool{} on real serverless workflows, asking: can it detect the four
defect classes before deployment (RQ1); can it recover the semantics \asl{} omits
cheaply enough to analyse existing workflows (RQ2); and what does verification cost,
at build and run time (RQ3)? Every number below is produced by the released tool over
a committed corpus and is reproducible with the commands shown.

\subsection{Setup and corpus (RQ1)}
\label{sec:eval:corpus}

We mined \textbf{193} Step Functions workflows from two public AWS repositories,
\texttt{aws-samples/}\allowbreak\texttt{aws-step\-func\-tions-examples} and
\texttt{aws-samples/}\allowbreak\texttt{step-func\-tions-workflows-collection}, taking every file that
parses as an \asl{} state machine. The corpus (Fig.~\ref{fig:eval}) is realistic
and diverse: 1{,}355 states in total, a median of 6 states per workflow (max 33;
Fig.~\ref{fig:eval}a), and broad use of \texttt{Choice} (166), \texttt{Map} (64),
\texttt{Parallel} (33; Fig.~\ref{fig:eval}b), retries (84 workflows), and catch handlers
(51 workflows). All experiments ran on a commodity laptop with a release build of
\tool{} (Rust~1.96).

\subsection{Findings in the wild (RQ1)}
\label{sec:eval:wild}

Run unmodified over the corpus (with inference enabled), \tool{} flags
\textbf{86 of 193} workflows. We separate \emph{sound native} findings, which need no
annotations and which we manually confirmed, from \emph{inference-driven} findings,
which are warnings requiring triage (Table~\ref{tab:wild}). Among the native
findings, nine workflows contain a \texttt{Choice} with no \texttt{Default}
(\code{SC0007})---a recognised cause of \texttt{States.NoChoiceMatched} run-time
failures---and one is genuinely malformed (\code{SC0010}): an aws-samples example
nests a top-level \texttt{QueryLanguage} directive \emph{inside} its \texttt{States}
block, where Step Functions would reject it. The inference-driven warnings
(\code{SC3001}: 36; \code{SC4001}: 117) mark non-idempotent tasks retried broadly and
persistent tasks lacking a compensation path; as Section~\ref{sec:eval:infer} shows,
these are high-recall but include false positives (e.g.\ a \texttt{RefundPayment}
compensator inferred as needing its own compensation), which is precisely why they
are surfaced as warnings rather than errors.

\subsection{Mutation-based detection (RQ1)}
\label{sec:eval:mut}

Because correct real workflows expose few of the deeper defects, we measure detection
power by \emph{error injection}. For each defect class we inject exactly one defect
per applicable workflow with \texttt{stepcheck mutate} and re-verify; a defect counts
as \emph{detected} only if the expected diagnostic's count strictly increases over the
unmutated baseline (so we measure detection of the \emph{injected} defect, not
pre-existing findings). Across \textbf{429} mutants spanning the four classes,
\tool{} achieves \textbf{100\% recall} (Table~\ref{tab:mut}), and it never reports the
expected defect on the corresponding originals. We stress that this measures
\emph{reliability of each check on the defect class it targets}, not detection of
arbitrary bugs; the mutations are constructed to fall within each check's remit.

\subsection{Inference accuracy (RQ2)}
\label{sec:eval:infer}

The semantic checks depend on recovering idempotency and persistence. We hand-labelled
a gold standard of \textbf{44 tasks} across 10 workflows (spanning a Saga, an
inventory domain, account vending, data quality, and text processing), labelling each
task by its true operational semantics, and compared the inference to it
(Table~\ref{tab:infer}). The heuristic abstains on $\sim$20\% of tasks (unconventional
verbs such as \emph{confirm}, \emph{audit}, \emph{aggregate}); on the tasks it does
classify it reaches \textbf{82.9\%} accuracy for idempotency and \textbf{91.4\%} for
persistence (Fig.~\ref{fig:eval}c). Its errors are instructive and bounded: \emph{cancel} operations
(idempotent in effect) are flagged non-idempotent, and a \emph{refund} compensator is
flagged persistent. Because inference only supplies \emph{defaults}, a one-line
annotation corrects any such case, and all inferred findings are warnings. This
answers RQ2: useful semantics are recovered at zero authoring cost, with residual
error made visible and cheaply correctable.

\subsection{Verification cost and runtime overhead (RQ3)}
\label{sec:eval:cost}

Verification is cheap. Averaged over the corpus, the five passes take \textbf{18.7}\,$\mu$s
per workflow (median 14.9\,$\mu$s, max 111.8\,$\mu$s); the entire 193-workflow corpus
verifies in \textbf{3.6\,ms}. Because all analysis happens before deployment and the
output is ordinary \asl{}, the \emph{runtime} overhead introduced by \tool{} is
\textbf{zero}: the generated workflow executes on the standard Step Functions runtime
with no added middleware, sidecar, or instrumentation. This distinguishes \tool{}
from runtime approaches to fault tolerance and transactions~\cite{zhang2020beldi,burckhardt2021durable}.

\subsection{Conciseness and AWS round-trip}
\label{sec:eval:roundtrip}

The typed DSL is also more concise than the \asl{} it generates: the order workflow
is 20 declarative DSL statements that expand to a 121-line \asl{} definition while
additionally encoding five record schemas, a four-edge protocol, and per-task
idempotency, persistence, and compensation---semantics \asl{} cannot express.

Finally, to confirm the compatibility claim end-to-end, we deployed the DSL-verified
order workflow to real AWS Step Functions. The emitted \asl{} was deployed
\emph{unmodified} (only binding \texttt{FunctionName} to a deployed Lambda ARN) as an
Express state machine and executed synchronously; the execution reached
\texttt{SUCCEEDED} with the input propagating through all four task steps to the
terminal state, billed at 500\,ms / 64\,MB. The temporary resources were then removed.
A verified \tool{} workflow thus runs on the unmodified industrial platform.

\subsection{Cross-format generalization: CNCF Serverless Workflow}
\label{sec:eval:cncf}

To test that the approach generalizes beyond AWS, we added a third frontend for the
vendor-neutral CNCF Serverless Workflow DSL~\cite{cncfServerlessWorkflow} and ran it on
\textbf{66} example workflows from the specification's repository. The frontend lowers
the DSL's tasks (\texttt{call}/\texttt{do}/\texttt{fork}/\texttt{for}/\texttt{switch}/
\texttt{try}/\texttt{listen}/\dots) to the \emph{same} IR \emph{without changing the IR
or any analysis pass}, and parses all 66 workflows with no failures. The structural,
typestate, retry-safety, and compensation analyses apply unchanged; only the
\asl-specific data-binding checks (\code{SC1001}--\code{SC1003}) stay silent---correctly,
since the CNCF DSL uses runtime expressions rather than JSONPath. A mutation study on
this corpus detects every injected defect for which the class has an injection site
(retry 4/4, structural 9/9); contract- and compensation-class mutations have no sites in
these mostly single-task feature demos.

Crucially, the CNCF DSL can declare JSON Schemas for task input and output. Where it
does, the typed contract check (\code{SC1010}) runs at \emph{full precision with no
inference}: a reordered, schema-annotated order workflow is rejected with three
\code{SC1010} errors derived directly from the declared schemas (e.g.\ \texttt{shipOrder}
requires \texttt{paymentId}, which its new predecessor does not produce)---the same
defect the inference layer only approximates on raw \asl, here established exactly. The
asymmetry is informative: CNCF makes data contracts explicit, closing that gap natively,
but---like \asl---leaves idempotency and compensation implicit, so those checks still
rely on annotation or inference in both ecosystems.

\subsection{Threats to validity}

\emph{Construct.} The mutation study reports 100\% recall by design: each mutation
targets a defect within a check's remit, so the result attests to the reliability of
each check, not to coverage of all possible bugs. We report it alongside the
in-the-wild findings, which are not constructed. \emph{Internal.} Gold labels for
idempotency/persistence are judgements; we documented our labelling criteria and
release the labels for scrutiny, and the contested cases (cancel, refund) are exactly
where the paper claims inference is imperfect. \emph{External.} The corpus is drawn
from AWS sample repositories, which may over-represent didactic workflows; we mitigate
this by taking \emph{all} parseable workflows rather than a curated subset, yielding a
realistic spread of sizes and features. \emph{Soundness.} The native contract checks
are conservative (they flag only definite faults); typestate and typed-contract
precision depend on annotation quality, which is why \tool{} reports inferred findings
as warnings.
