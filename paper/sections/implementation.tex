\section{Implementation}
\label{sec:impl}

The framework of Section~\ref{sec:approach} is realised directly as \texttt{stepcheck}, a single
dependency-light Rust command-line tool of 5{,}045 lines that follows the pipeline of
Figure~\ref{fig:arch-detail}, covering eight analysis passes, three front ends, the \asl{}
emitter, and the self-validation tooling.

Two small extension interfaces realise the architecture: a \texttt{Frontend} lowers an input
format to the IR, and a \texttt{Pass} analyses that IR and emits diagnostics. Behind them sit the
typed DSL, raw \asl{}, and CNCF Serverless Workflow~\cite{cncfServerlessWorkflow}; adding the last
touched neither the IR nor any pass (Section~\ref{sec:eval:cncf}). The raw-\asl{} frontend lowers
generic JSON with a stack-growing deserializer, parsing all 193 corpus workflows and the
nested-\texttt{Map} stress cases without error.

\paragraph{Running the verifier.}
\tool{} is a single self-contained binary, packaged for \texttt{crates.io} and \texttt{npm}
(packaging details in the technical report). A developer runs \texttt{stepcheck check workflow.json}
on an existing definition; \texttt{--infer} lights up the semantic checks from name and resource
conventions, and \texttt{--annot sidecar.toml} promotes them from warnings to declared-tier errors
(Section~\ref{sec:approach:annot}). Findings render for a terminal or, with \texttt{--json}, as a
stable machine record (code, severity, state, message, remediation).

By default the exit status is \texttt{0} (clean), \texttt{1} (any \emph{error}), or \texttt{2}
(parse failure). The \emph{recommended CI policy} fails a build on errors---the sound native and
declared-tier findings---while leaving \emph{inferred warnings} non-blocking. This lets a repository
adopt \tool{} without triaging heuristic findings up front. \texttt{--deny-warnings} tightens the
gate once a workflow is annotated. The artifact ships a copy-pasteable GitHub Actions gate.

Nothing else is deployed: the check reads the ingested \asl{} and never re-emits it, so raw-\asl{}
verification is entirely independent of the emitter.

The remaining components validate the verifier itself. A code-disjoint execution oracle
re-interprets a workflow concretely along each acyclic path and cross-checks every data-flow
finding---disjointness matters because a shared transfer-function bug would otherwise validate
itself---turning the soundness theorem into a tested property (Section~\ref{sec:eval:dataflow}).
A mutation command injects one defect of a chosen class and re-emits deployable \asl{} for the study
in Section~\ref{sec:eval}.

\paragraph{Implementation limitations.}
Distributed \texttt{Map} item contexts are modelled coarsely. The \asl{} emitter---used as the
DSL's code generator and in evaluation harnesses---preserves control flow, retries, catches, and
per-state timeouts, but does not yet claim full-fidelity regeneration of arbitrary ingested
\asl{} I/O-processing fields.
