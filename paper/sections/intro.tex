\section{Introduction}
\label{sec:intro}

Serverless applications increasingly encode business processes as managed workflows. In AWS Step
Functions, the executable artifact is an Amazon States Language (\asl) state machine: JSON for task
calls, branches, retries, parallelism, and error handling~\cite{awsStepFunctions}. These workflows
charge cards, reserve inventory, move documents, and coordinate human approvals, so latent workflow
bugs become production failures rather than local exceptions.

Figure~\ref{fig:intro} uses a production proxy rather than a synthetic order graph. The application
is a widely reused public benchmark: Eismann et al. use AWS Serverless Airline Booking as the
canonical case application in their study of serverless performance-test stability~\cite{eismann2022stability},
a line of work with roughly 30 citations in the serverless literature. In the upstream template, an
AppSync resolver builds the execution input from frontend booking fields, but the state machine
itself starts at \texttt{Reserve Flight}: it reserves a flight seat through DynamoDB, reserves the
booking, collects payment, confirms the booking, and notifies the customer. Its failure paths refund
payment, cancel the booking, release the seat, and send unresolved failures to a booking DLQ.

The markers show why syntax validation is not enough. \textbf{(1)} frontend/schema drift can make a
JSONPath read fail although the graph validates; \textbf{(2)} a one-edge ordering mutation can confirm
before payment; \textbf{(3)} retries around durable seat and booking effects are safe only under an
idempotency premise that \asl{} does not encode; and \textbf{(4)} Saga correctness depends on matching
persistent effects with compensation paths (Section~\ref{sec:bg:defects}). The two remaining
classes in \tool{}---parallel write interference and unbounded callbacks---are evaluated on other
public AWS and external workflows, not drawn into \texttt{ProcessBooking}, whose upstream \asl{} has
neither a \texttt{Parallel} state nor a callback task.

Existing validators check that the JSON is well-formed, transitions exist, and paths are syntactic
\cite{awsStatelint,aslValidator,awsValidateDefinition}. They do not know whether a task produces
the field its successor reads, whether a retry is safe for a non-idempotent effect, whether two
branches race on one resource, or whether a durable effect is compensated after failure. The
missing facts are semantic: task contracts, protocol states, idempotency, write footprints, time
bounds, and compensators. Durable-execution systems enforce recovery at run
time~\cite{burckhardt2021durable}, not before deployment.

We present \tool{}, a static verifier for AWS Step Functions. Its thesis is simple: verify the
\emph{deployed artifact} under \emph{layered semantics}. The unifying contribution is a single
workflow IR: its native facts support sound or deliberately under-approximating checks, and the
business facts \asl{} omits are recovered as provenance-labelled premises. Native facts in \asl{} support immediate structural, data-flow, temporal, and
conservative concurrency checks. Facts \asl{} omits can arrive from a sidecar, typed DSL,
generated metadata, or lightweight inference; \tool{} grades findings by that provenance, so
inferred facts produce warnings while declared facts produce errors relative to the declared model.
Adoption therefore starts on raw \asl{} and strengthens as teams add semantics.

The core technical result is a flow-sensitive JSON-shape analysis for \asl{}'s I/O pipeline: it
reports a missing-field access only when every execution reaching the read lacks the field
(Theorem~\ref{thm:soundness}). Around it, seven further passes cover structural correctness,
typed contracts, typestate ordering, retry safety, Saga compensation, conservative concurrency,
and temporal bounds.

\paragraph{Contributions.}
\begin{itemize}
  \setlength{\itemsep}{1pt}
  \item A deployed-artifact verification architecture for \asl{} with native and declared semantic layers.
  \item A no-false-positive data-flow analysis for missing JSON fields (under the modeled JSONPath semantics), plus workflow checks for retry, ordering, concurrency, time, and compensation.
  \item A Rust implementation with raw \asl{}, typed-DSL, and CNCF Serverless Workflow front ends.
  \item Evidence on 193 AWS and 66 CNCF workflows, plus 95 from independent repositories: six real bugs rediscovered, 88/126 missing-field mutants detected with all 92 emitted reports oracle-confirmed, and 100\% recall on 616 targeted mutants produced by \tool{}'s mutator.
\end{itemize}
