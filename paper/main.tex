\begin{abstract}
Serverless workflow orchestration platforms such as AWS Step Functions coordinate
fleets of functions and managed services, but their workflows are written as
untyped JSON state machines (the Amazon States Language, \asl) whose correctness is
checked only at run time. Incompatible task interfaces, out-of-order business
transitions, unsafe retries of non-idempotent operations, and missing
compensations therefore surface as production incidents rather than build errors.
We present \tool, a static verifier that brings four complementary checks
---data-contract compatibility, typestate (business-protocol) conformance, retry
safety, and Saga compensation completeness--- to workflows \emph{before}
deployment, and compiles verified workflows back to executable \asl{}. Because
real \asl{} omits the semantics these checks need (task types, idempotency,
compensation), \tool{} pairs sound native analyses with a lightweight annotation
layer whose defaults are \emph{inferred} from task names and resource bindings,
so existing workflows can be analysed with zero up-front effort and refined
incrementally. \tool{} is implemented in Rust as a modular frontend/pass pipeline
(2.6k LOC) and evaluated on a corpus of \textbf{193} real Step Functions
workflows mined from public AWS repositories. The native checks flag genuine
defects in the wild; a mutation study injecting 429 defects of four classes is
detected with 100\% recall; name-based inference reaches 83--91\% accuracy
against a hand-labelled gold set; verification costs 19\,$\mu$s per workflow on
average; a verified workflow deploys and executes unmodified on AWS Step
Functions with zero runtime overhead; and the architecture generalizes to a second
workflow language (CNCF Serverless Workflow) with no change to the analyses.

\keywords{Serverless computing \and Workflow orchestration \and AWS Step Functions
\and Static verification \and Typestate \and Saga transactions \and Domain-specific
languages.}
\end{abstract}
